# Clear project instructions

Write instructions that identify the accepted behavior, its reason and the condition under which it applies. Use [official Claude Code memory documentation](https://code.claude.com/docs/en/memory) for runtime mechanics.

## Concrete scope

“Use the existing import parser so both callers reject malformed records consistently” is actionable when the parser exists. “Follow best practices” does not define a result. Verify the file and behavior before adding a pointer.

Distinguish requested assessment from implementation. An authorized correction should proceed through its relevant verification; an explicit checkpoint still binds. Silence grants neither new scope nor external-action authorization.

## Proportionate detail

Show a short example when the output format matters. Use the actual project convention rather than a stock framework rule. Avoid compulsory section counts, file-reading quotas and unsupported performance claims.

Keep the reason for consequential constraints. Clear wording usually makes capitalized emphasis unnecessary. State enforceable boundaries in the host's permission or hook configuration; prompts describe intent but do not replace enforcement.

## Loading and continuity

Keep root instructions as the index and universal decisions. Path-scoped rules remain conditional when discovered by their matching paths; eagerly importing them defeats that property. Use task-local notes and host compaction when available, under the applicable memory permissions.

## Verify changes

Check that a normal task still gets the intended behavior and an adjacent task avoids irrelevant guidance. Judge source preservation, authorization and completion from actual artifacts. A self-assigned score or shorter line count is not evidence of better agent performance.
